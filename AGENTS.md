## Product and engineering rules

Roblox PC is the active target. Preserve existing web, touch, SV/EN and positive
female Ugneta. No new web features without a new product decision.
Shared rules and geometry keep their canonical source; do not introduce a
second Luau truth or weaken existing regression checks.

UBRF is the real place, not inspiration. Never invent missing measurements,
horse facts or room functions. Mark REFERENCE GAP / ASSUMPTION explicitly.
Check relevant raw photos/video and plans before claiming a visual source gap.
Do not repeat the completed blocked horse-asset search without new evidence.

Work on a scoped feature branch with one responsibility. Read the actual code
and local status first, preserve other writers' files, and test the real
production path with isolated adapters. Define observable success, negative
cases and lifecycle boundaries before coding. A test that cannot turn red is
weak evidence. Missing runtime or device evidence is NOT_TESTED, not PASS.

No agent can implement and independently approve the same substantial change.
Technical checks or merge do not grant product acceptance. Do not infer push,
publication, installation, extra agents or deletion permission from a cleanup
or implementation request; use the current working agreement.
